# Как обновляется библиотека после запуска бота

## Главное

**Добавление книги не требует обновления Telegram-бота и не требует новой версии кода.**

Telegram — только интерфейс.

Библиотека живёт в backend/database.

Схема:

```text
новый PDF
→ Source Catalog record
→ PDF ingestion
→ страницы / разделы / chunks
→ embeddings
→ RAG
→ книга доступна следующим запросам
```

После успешной индексации новый источник начинает использоваться без перезапуска Telegram.

## Когда перезапуск НЕ нужен

- добавлена новая книга;
- заменён PDF книги;
- добавлен дополнительный источник;
- обновлены embeddings конкретной книги;
- изменён статус PRIMARY/SECONDARY;
- обновлены Topic→Source связи в базе.

## Когда обычно нужен restart/redeploy

- изменился Python-код;
- изменились `.env` параметры;
- изменилась структура БД;
- обновился Telegram-интерфейс;
- сменился embedding model/dimension для всей библиотеки;
- обновлена системная инфраструктура.

## Административная загрузка книги

v1.4 имеет endpoint:

```text
POST /api/v1/admin/library/books
```

Передаётся:
- PDF;
- название;
- автор;
- предмет;
- класс;
- уровень;
- год;
- PRIMARY/SECONDARY.

Endpoint:
1. создаёт Source;
2. импортирует PDF;
3. извлекает текст/страницы;
4. создаёт chunks;
5. запускает embeddings;
6. сообщает, нужен ли OCR.

В ответе:

```json
"bot_restart_required": false
```

## Если вы прислали книгу в ChatGPT

Я могу:
- проверить файл;
- определить метаданные;
- подготовить его к Source Catalog;
- проверить качество текстового слоя;
- подготовить import/update пакет;
- сказать, какую команду выполнить.

Но для изменения **живого сервера** файл должен быть загружен туда через admin endpoint/панель либо при наличии доступного подключённого инструмента к этому серверу.

Цель следующих версий — сделать для владельца отдельную кнопку/веб-панель «Добавить книгу», чтобы команды вообще не требовались.
